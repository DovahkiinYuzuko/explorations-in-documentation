# 絵文字混入の任意制御ガイド（Optional Emoji Control）

本リファレンスは、書き手（ユーザー）が「この文書には絵文字を使わない」方針を選んだ場合、または既存文書に対する絵文字混入の検査を求められた場合に **のみ** 参照するオプトイン手順書です。

AIエージェントは学習時のフォーマットバイアスにより、意図せず見出しや箇条書きへ絵文字を混ぜてしまうことがあります。この手順は、書き手の表現を勝手に検閲・削除するためのものではなく、「使わない」と決めた文脈で AI 側の意図しない混入を防ぐ安全装置として機能します。

## 1. 発動条件（オプトイン原則）

以下のいずれかに該当する場合にのみ、本手順を適用します。
- Step 2 の方針確認で、書き手と「絵文字を使わない方針」で合意した場合
- ユーザーから「絵文字を除去してほしい」「絵文字が含まれていないかチェックしてほしい」と明示的に依頼された場合

対象文書に書き手が意図して配置した絵文字が含まれており、抑制や除去の合意がない状態では、本手順による削除やスクリプトの強制適用を行いません。

## 2. 2段階の抑制と検証ループ

絵文字の混入を防ぐ際は、執筆時の抑制（ソフト制約）と出力後の機械検査（ハード制約）を組み合わせます。

1. **生成・編集時の抑制（ソフト制約）**:
   - 見出し、箇条書き、表、本文、および引用コメント内に Unicode 絵文字（装飾記号を含む）や Markdown 絵文字ショートコード（`:rocket:`, `:white_check_mark:` 等）を出力しないように記述します。
   - 強調や状態表現が必要な場合は、絵文字ではなく見出し階層、Markdown の標準リスト記号（`-`, `1.`）、または `[NOTE]` / `SUCCESS` 等の明確なテキスト表記を用います。
2. **スクリプトによる機械検査（ハード制約）**:
   - 出力後（または対象ファイルの編集後）に、スクリプトのソースコードは読まずブラックボックスとして実行します（引数の確認が必要な場合は `--help` のみを実行します）。
   - 実行コマンド（対象プロジェクト側を作業ディレクトリとしている場合は、本スキル格納ディレクトリの実パスを補って呼び出します）:
     ```bash
     python scripts/detect_emoji.py <対象ファイル>
     ```
   - **終了コード `1`（検出あり）の場合**: 出力された行・列および該当トークンを確認し、意図しない絵文字やショートコードを取り除いたうえで、終了コード `0` になるまで再実行します。
   - **終了コード `2`（実行エラー）の場合**: パス指定や文字コードを確認します。

## 3. `scripts/detect_emoji.py` のオプション使い分け

対象ファイルの形式や検査の厳しさに応じて、以下のオプションを使い分けます。

| オプション | 挙動と使いどころ |
| :--- | :--- |
| （指定なし） | 拡張子（`.md`, `.markdown`, `.mdx`, `.mkd`, `.mdown`）から Markdown モードを自動判定し、コードブロック・インラインコード・URL・YAMLフロントマター・IPv6 等を除外して検査します。 |
| `--markdown` / `--no-markdown` | 拡張子によらず Markdown マスクおよびショートコード検査を強制オン／オフします。プレーンテキスト（`.txt`）やコード内コメントでは `--no-markdown` またはデフォルトが適しています。 |
| `--strict` | VS16（絵文字表示セレクタ）が付いていない非 ASCII テキスト記号（`U+2764`, `U+26A0` 等）も検出対象に含めます。記号全般の混入を厳しく止めたい場合に指定します。 |
| `--strict-only` | スクリプト同梱の Unicode RGI / `Emoji_Presentation` 一覧のみを検査し、将来の新設ブロック等を想定した構造候補フォールバックを無効にします。 |
| `--no-indented-code-mask` | Markdown モード時に 4スペースインデントをコードブロックとして除外せず検査対象に含めます。 |
| `--json` | 検出結果を機械可読な JSON 形式で出力します。 |
| `--version` | 同梱されている Unicode データのバージョン情報を表示します。 |

## 4. スクリプトの限界と目視確認の併用

`scripts/detect_emoji.py` は決定論的な補助検査ツールとして機能しますが、**検知スクリプト単体で完璧な網羅・判定ができるわけではありません**。終了コード `0` だけを根拠に完了とみなさず、必ず目視確認と併用します。

- **見逃し（偽陰性）の余地**: スクリプト同梱データの Unicode バージョン以降に追加された新しい絵文字、テキスト顔文字（`:-)` 等）や ASCII 記号による装飾、あるいは Markdown のコードブロック／インラインコードと誤認された箇所内の絵文字は検出から漏れる可能性があります。
- **誤検知（偽陽性）の余地**: 特殊な URL 構文、数式・独自記法内のコロン囲み（`:name:`）、技術仕様の説明例として意図的に記載した記号などが検出される場合があります。

そのため、スクリプトで終了コード `0` を確認した後も、出力テキスト全体を人の目（または最終の全文点検）で見直し、意図しない絵文字や記号が紛れ込んでいないかを確認します。
