### 概要
本リポジトリは、生成AI（LLM）がドキュメントを作成する際に「文章を過剰に装飾し、機械的検証を省略しがちである」という性質に着目した個人的な自由研究です。
認知心理学の実証データや形式論理学の枠組みをエージェントへの「工学的制約」として課すことで、大言壮語を抑え、読者の認知負荷を低減し、事実と制約に誠実な技術文書（README、仕様書等）を出力させることを狙ったエージェントスキル `doc-refine` を提供します。

---

### スキルの実行風景

エージェントに対して本スキルの実行を指示した際の、実際の対話および診断出力の実例です（本リポジトリの `README.md` を監査させた際のトランスクリプト）。

```markdown
> ユーザー:
> README.md を doc-refine の規準で監査して！

> エージェント:
> doc-refine の5層フレームワークに則って、対象ドキュメントの監査（Phase 1）を実施しました。

### 監査サマリー
| レイヤー | 観点 | 判定 | 主な検出事項・改善ポイント |
| :---: | :--- | :---: | :--- |
| **L1** | First View & 離脱防止 | WARN | LSP One-Linerの入出力規定が抽象的、Visual Proofの欠落 |
| **L2** | 構成 & 段階的開示 | WARN | 多言語（日本語・英語）の単一ファイル縦積みによるスクロール肥大化 |
| **L3** | 信頼性 & 両面提示 | PASS | 誇張語の排除、制約事項が「事実・理由・代替策」の3連タプルを充足 |
| **L4** | 論理構造 & 事実規範分離 | PASS | 「べきである」等の規範的説教を排除し、客観的因果文へ統一 |
| **L5** | 実証根拠 & 再現可能性 | WARN | 実行後の決定論的期待出力スニペットの欠落 |

---
**[Phase 2: 対話選択・強制一時停止]**
プロトコルに基づきターンを停止します。次のアクションを選択してください：
[1] フルリライト（全5層の改善を反映した完全版を出力）
[2] 対話型ステップバイステップ（層ごとに確認・承認）
[3] 特定レイヤーのみ修正
[4] 診断のみで終了（ドキュメント変更なし）
```

上記のように、エージェントは自己判断で勝手にドキュメントの書き換えを強行せず、Phase 1で客観的診断表を提示した直後にターンを強制停止し、人間の指示を待ちます。

### 導入方法

お使いのエージェント環境に応じて、以下のいずれかの方法でスキルを追加します。

**汎用エージェント環境（Skills CLI 対応環境）:**
```bash
npx skills add DovahkiinYuzuko/explorations-in-documentation --skill doc-refine
```

> [!WARNING]
> **Skills CLI と Antigravity のスコープ境界に関する注意**
> `npx skills add`（Skills CLI）は、カレントプロジェクトの `.agents/skills/` または対応クライアント（Claude Code, Cursor等）の固有ディレクトリにスキルを配置する仕様です。
> `npx skills add -g` を実行した場合でも、**Antigravity のグローバル設定領域（`~/.gemini/config/skills/`）には自動登録されません**。Antigravity 環境全体で常時利用する場合は、以下の個別手順を参照してください。

<details>
<summary>Antigravity 環境でのインストール・利用手順</summary>

Antigravity でグローバルプラグインとして利用する場合は以下のコマンドを実行します：
```bash
agy plugin install DovahkiinYuzuko/explorations-in-documentation
```

または、対象ワークスペース直下の `.agents/skills/` ディレクトリ内に本リポジトリの `skills/doc-refine/` フォルダを配置することで、ワークスペースローカルスキルとして即時認識されます。
</details>

### スキルの呼び出しと使途

エージェントに対して対象ドキュメントを指定し、スキルを実行させます。

```text
/doc-refine README.md
```

- **使途と振る舞いの設計**:
  本スキルは、以下の3フェーズで動作するように設計されています。
  1. **Phase 1（5層診断）**: 対象ドキュメントをL1〜L5の各観点（ファーストビュー、情報構造、信頼性、論理、実証根拠）から評価し、問題点と改善案を提示します。
  2. **Phase 2（対話選択・強制一時停止）**: エージェントが勝手に書き換えを先走らないよう、診断提示後に必ずターンを強制終了し、読者の指示（全リライト、個別確認、診断のみ等）を待ちます。
  3. **Phase 3（改善出力）**: 読者の承認に基づき、制約やトレードオフを開示したドキュメントを出力します。

### 5層フレームワークによる制御の狙い

エージェントに対して以下の5つのレイヤーに基づく制約を与え、出力の整流を試みています。

- **Layer 1: ファーストビュー & 離脱防止**:
  読者が最初に目にする画面（スクロール前）で、ツールの本質と最小限の実行手順を伝達させ、認知の摩擦による離脱を抑止する狙いです。
- **Layer 2: 構成 & 段階的開示**:
  作業記憶（ワーキングメモリ）の容量限界に配慮し、初見に必要な最短ルート（ハッピーパス）と深層リファレンスを関心事の分離（SoC）によって折りたたませる狙いです。
- **Layer 3: 信頼性 & 両面提示**:
  客観的検証のない誇張語（BAKAワード）を削ぎ落とし、制約事項を「制約事実 ＋ 設計理由 ＋ 代替策」の3連タプルで誠実に開示させる狙いです。
- **Layer 4: 論理構造 & 事実規範分離**:
  「開発者は〜すべきである」という規範的説教をヒュームのギロチンに基づき排除し、客観的な条件付き因果文（「［前提］の場合、［手段］により［結果］が担保される」）へ正規化させる狙いです。
- **Layer 5: 実証根拠 & 再現可能性**:
  測定文脈を欠いた浮遊した数値を排除し、読者が手元で検証可能な単体実行可能コマンドと測定諸元をセットで提示させる狙いです。

### 制約事項とトレードオフ

本スキルの設計上の境界条件とトレードオフを開示します。

- **対話的折りたたみ表現のマークアップ環境依存**:
  - *制約事実*: スキルのデフォルトテンプレートが提示する `<details>` による開閉表現は、MarkdownおよびHTMLレンダラを備えた環境に依存します。
  - *設計理由*: 初見読者のワーキングメモリを保護しつつ、能動的探索感（Information Scent）を与えるUI実装としてマークアップ構文を採用しているためです。
  - *代替策・推奨構成*: プレーンテキスト（.txt）、RFC、社内仕様書等の非マークアップ環境では、本質である「グルーピング × SoC」を維持したまま、末尾付録（Appendix）分離または外部ファイルポインタ分離として適用します。
- **情緒的記事・マーケティング文章への非適合**:
  - *制約事実*: 本フレームワークは、ポエム、情緒的エッセイ、過剰な感情訴求を主目的とするセールスレターの執筆には適合しません。
  - *設計理由*: 形式論理、反論あり両面提示、および客観的事実命題への整流を最優先として設計されているためです。
  - *代替策・推奨構成*: 感情的共感や購買意欲喚起を主目的とする文書には、本スキルではなく従来のセールスコピーライティング技法を適用します。
- **エージェント環境間のスキル配布先分断**:
  - *制約事実*: Skills CLI（`npx skills add`）によるグローバルインストールは、Antigravity のグローバル設定ディレクトリ（`~/.gemini/config/skills/`）に対応していません。
  - *設計理由*: 各エージェントエコシステムごとにスキル配置仕様が標準化途上であり、ディレクトリ探索優先度が異なっているためです。
  - *代替策・推奨構成*: Antigravity 環境では `agy plugin install` を使用するか、ワークスペース直下の `.agents/skills/` に配置する構成をとります。
