### 概要
生成AI（LLM）が技術文書を作成する際、「根拠のない大袈裟な言葉で文章を盛り、機械的検証を省略しがちである」という性質に着目した個人的な自由研究です。

単なる「てにをは」の校正や画一的な穴埋めテンプレートの強制ではなく、「人間はどう文章を走査し、どの論理構造に納得し、何によって信頼を形成するのか」を57件の先行研究から紐解き、READMEをはじめとする技術文書全般に応用できる情報設計の仮説モデルとして提案しています。

### 本自由研究で提案する設計原則（仮説モデル）の要点

詳細は本編 **[`PAPER.md`](./PAPER.md)** にて論じていますが、本研究で提案する仮説モデルの主な視点は以下の5点です。

1. **視線と初動の科学（Attention & Onboarding）**:
   閲覧時間の57%が最初の画面（Above the Fold）に集中する傾向と、OSSの約75%以上で欠落している「なぜ作ったのか（Why）」「いつ使うか（When）」の需給ギャップを踏まえ、最初の数秒での迷いと「騙しの床（False Floor）」を減らす構成を目指します。
2. **認知負荷と段階的開示（Cognitive Load & Progressive Disclosure）**:
   初見情報に対する作業記憶の容量（$4 \pm 1$ チャンク）と「読者は要約ではなく深い情報を好む」という実験知見を両立させるため、情報を削るのではなく「グルーピング × 関心事の分離（SoC）」によって最短動線と深層仕様を階層分離するアプローチをとります。
3. **論理と必然性の骨格（Logic & Necessity）**:
   前提となる不便から解決機能・設計構造への演繹的なつながりを示し、ヒュームのギロチンに照らして「〜すべき」という規範的説教を「仕様事実と条件付き因果文」へと置き換えることで、押し付けがましさの低減を図ります。
4. **信頼と反論あり両面提示（Credibility & Signaling）**:
   美辞麗句（チープトーク）を控え、比較ベースラインと測定環境、手元で追試できる検証コマンド、そして「制約事実 ＋ 設計上のトレードオフ理由 ＋ 回避策」を揃えた反論あり両面提示によって、信頼性の向上が期待されます。
5. **画一的テンプレートの否定と文脈適応（Context Adaptation）**:
   決まった見出しの穴埋めテンプレートを多くの文書に一律適用するのではなく、CLIツール、ライブラリ、内部仕様書、あるいはジョークアプリといった対象の性質と目的に応じて原則の重み付けを変化させる運用を想定しています。

### エージェントスキル `doc-refine` の導入方法

お使いのAIエージェント環境に応じて、以下のいずれかの方法でスキルを追加できます。

**汎用エージェント環境（Skills CLI 対応環境）:**
```bash
npx skills add DovahkiinYuzuko/explorations-in-documentation --skill doc-refine
```

> [!WARNING]
> **Skills CLI と Antigravity のスコープ境界に関する注意**
> `npx skills add`（Skills CLI）は、カレントプロジェクトの `.agents/skills/` または対応クライアント（Claude Code, Cursor等）の固有ディレクトリにスキルを配置する仕様です。
> `npx skills add -g` を実行した場合でも、**Antigravity のグローバル設定領域（`~/.gemini/config/skills/`）には自動登録されません**。Antigravity 環境全体で常時利用する場合は、以下の個別手順を参照してください。

<details>
<summary>Antigravity 環境でのインストール・利用手順</summary>

Antigravity でグローバルプラグインとして利用する場合は以下のコマンドを実行します：
```bash
agy plugin install DovahkiinYuzuko/explorations-in-documentation
```

または、対象ワークスペース直下の `.agents/skills/` ディレクトリ内に本リポジトリの `skills/doc-refine/` フォルダを配置することで、ワークスペースローカルスキルとして即時認識されます。
</details>

### 制約事項とトレードオフ

本研究の仮説モデルおよびスキルの境界条件とトレードオフを開示します。

- **異分野統合モデルとしての未検証性（仮説段階であること）**:
  - *制約事実*: 参照している57文献の個別知見にはそれぞれ実験や調査の裏付けがありますが、それらを統合した本モデル自体について、大規模な被験者実験（A/Bテスト等）による直接的な実証は現時点で行われていません。
  - *設計理由*: 個人的な自由研究として、まずは散在する各分野の知見から演繹的に「読みやすいドキュメントの設計仮説」を組み立て、AIエージェントのスキルとして試作することを主目的としているためです。
  - *代替策・推奨構成*: 本リポジトリが提示する原則は確定した法則ではなく、「こう設計すればこうした効果が期待できる」という仮説の引き出しとして参照し、実際の読者層やプロジェクトの反応に応じて取捨選択・調整する運用を想定しています。
- **情緒的記事・純粋なセールスコピーへの非適合**:
  - *制約事実*: 本フレームワークは、小説、ポエム、情緒的エッセイ、または感情的な高揚感によって購買を促す消費者向けセールスレターの執筆には向いていません。
  - *設計理由*: 形式論理、反論あり両面提示、および客観的事実命題への整理を重視して設計されているためです。
  - *代替策・推奨構成*: 感情的共感やストーリーの余韻を主目的とする文書には、本モデルではなく従来のレトリックや物語論の技法を用いる方が適しています。
- **対話的折りたたみ表現のマークアップ環境依存**:
  - *制約事実*: `<details>` タグによるアコーディオン開閉表現は、MarkdownおよびHTMLレンダラを備えた環境に依存します。
  - *設計理由*: 初見読者のワーキングメモリを保護しつつ、同一ページ内で能動的に深層情報へアクセスできるUI実装としてマークアップ構文を利用しているためです。
  - *代替策・推奨構成*: プレーンテキスト（.txt）、RFC、コード内コメント等の非マークアップ環境では、基本構造である「グルーピング × 関心事の分離（SoC）」を維持したまま、末尾付録（Appendix）への分離または外部ファイルポインタ分離として適用できます。
- **エージェント環境間のスキル配布先分断**:
  - *制約事実*: Skills CLI（`npx skills add`）によるグローバルインストールは、Antigravity のグローバル設定ディレクトリ（`~/.gemini/config/skills/`）に対応していません。
  - *設計理由*: 各エージェントエコシステムごとにスキル配置仕様が標準化途上であり、ディレクトリ探索優先度が異なっているためです。
  - *代替策・推奨構成*: Antigravity 環境では `agy plugin install` を使用するか、ワークスペース直下の `.agents/skills/` に配置する構成をとります。
